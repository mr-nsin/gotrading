01 — Codebase reality

Where the product stands today

The repository holds two different products. The planning docs (docs/01_Product_Vision.md through 17_AI_Context.md) describe an aspirational concept called "3Option" — Hinglish voice commands ("Nifty 22000 straddle sell karo") parsed by an LLM into multi-leg option orders via Sarvam AI, executed through Fyers. None of that is implemented; there is no speech capture, no STT/TTS, no LLM intent parser anywhere in the code — backend/main.py even still returns "Welcome to 3Option API" as its root response, a leftover from that naming.

What's actually built, under the name GoTrading, is a multi-broker algorithmic trading dashboard: a Next.js/AG Grid/Recharts frontend and a FastAPI/PostgreSQL/Redis backend, with adapters for eight brokers (Zerodha, Fyers, Upstox, Dhan, Angel One, 5paisa, Aliceblue, Kotak Neo), a strategy orchestrator running eight algo strategies (delta hedging, gamma scalping, statistical arbitrage, volatility skew, etc.), a risk manager with kill-switch fields, a backtester, and a paper-trading engine (VirtualTrade/VirtualPortfolio). By default the backend fabricates ticks, Greeks, and order fills to keep the dashboard looking alive — real broker wiring exists but isn't the default runtime path.

Tech debt already flagged by the repo's own audits

Three separate self-authored audits already sit in docs/review/, docs/CODE_ANALYSIS_REPORT.md, and docs/MULTI_EXPERT_ANALYSIS_REPORT.md. Their findings matter directly to any pivot, because a scalping terminal amplifies every one of these by pushing order volume and tick frequency far higher than a slower systematic-strategy dashboard would.

Why this matters for a scalper pivot

The multi-broker adapter layer, risk engine, and paper-trading models are the hard, reusable parts of a scalping terminal — building those from zero is most of the effort. The gap is in execution UX (ladder, hotkeys, multi-chart) and in the low-latency data path (MessagePack is already a dependency but isn't used for true tick streaming yet). The tech-debt table above is not optional cleanup — a scalper drives far more orders/sec and ticks/sec through exactly the code paths flagged as unsafe.

Regulatory direction

SEBI has been deliberately shrinking speculative retail options activity — fewer weekly expiries, larger lot sizes — while simultaneously building a compliance framework for algo trading rather than banning it. Read together, the message is: automate if you must, but with guardrails — not trade faster and more often.

One new development changes the calculus for a speed-focused product specifically: SEBI has proposed removing the rule that restricts Direct Market Access (DMA) to institutional clients, opening the door for retail investors to eventually get DMA-level order paths. NSE cash-segment DMA volume already hit 4.7% in May 2026, a nine-month high. This is a live tailwind for "faster execution" as a category — but it is a proposal in progress, not yet a right any retail platform can build on.

Internal sizing (unverified against third-party data)

The product team's own planning doc (docs/02_Market_Research.md) estimates a TAM of 10M+ active F&O traders in India, a SAM of ~2M tech-savvy traders on discount brokers, and a SOM of 10,000 paid subscribers in Year 1. These are internal working assumptions, not independently sourced — and given the FY26 SEBI data above, the TAM figure should be read as trending down, not flat, since it predates the confirmed 20% YoY drop in active F&O traders.

05 — Architecture constraint

Can a platform beat a broker on speed?

Before setting feature requirements, one architectural fact has to be settled, because it determines whether "millisecond execution" is a credible claim or a marketing trap.

A broker-agnostic platform sends an order to the broker's own API, which then submits it to the exchange. Every hop — app → GoTrading backend → broker API → broker's OMS → exchange — adds latency that a vertically integrated broker (Dhan, Fyers) simply doesn't have, because their app talks directly to their own OMS. No amount of clever engineering on GoTrading's side removes that extra network hop.

Illustrative order-path latency by architecture

Figures are directional: REST vs. WebSocket latency ranges reflect general trading-infrastructure literature, not a GoTrading measurement. Dhan's figure is the broker's own reported average. OptionX's "sub-millisecond" claim almost certainly describes ladder click-to-request time inside its own app, not the full network round trip to the exchange — no broker-agnostic platform can legitimately claim sub-millisecond exchange execution over the public internet.

The strategic fork

There are only two honest ways to win on speed as a non-broker: (1) compete on everything except the network hop — UI decision-to-submit time, ladder ergonomics, hotkeys, pre-validated orders, binary streaming — and market it as such; or (2) stop being a pure software layer and pursue actual DMA/broker status once SEBI's proposed retail-DMA rules land, which is a multi-year regulatory and capital undertaking. Recommendation: build (1) now, keep (2) as a two-to-three-year option, and never advertise network-level millisecond execution the platform cannot control.

06 — Verdict

Idea validation

The original thesis, revisited

The first pass of this research validated the underlying platform — multi-broker, risk-managed, compliance-first algorithmic execution — against the same market data used throughout this document. Two conclusions from that pass still hold and frame everything below: a systematic, risk-first platform rides the same regulatory tailwind as SEBI's new algo framework, while a mass-market "make speculative options trading faster and easier" pitch fights the tide of a shrinking, loss-making retail F&O population. The scalper pivot has to inherit the first instinct and avoid the second.

The scalper pivot, specifically

  • Validated
    Demand for fast, ladder-style execution is real and already monetised.OptionX charges up to ₹2,199/month and Sahi has built a whole broker around scalper UX — traders pay for this today.
  • Validated
    Multi-chart, single-screen layouts are the expected UX, not a novelty.Sahi's Scalper 2.0 (index + CE + PE + chain + P&L on one screen) and OptionX's ladder-centric layout confirm the pattern the user described is now table stakes for this category.
  • Caution
    The niche is contested by a well-capitalised, focused incumbent.OptionX already covers 13+ brokers, a price ladder, Greeks, 36+ strategy templates and free paper trading. Out-featuring it from a standing start is unlikely; out-executing it on reliability and compliance is more realistic.
  • Caution
    Vertically integrated brokers have a structural speed advantage no software layer can fully close.Dhan's <20ms is a floor set by owning the OMS. Compete on UX and risk controls, not on beating brokers at their own game.
  • Risk
    Scalping is the exact behaviour SEBI's own data says destroys retail wealth.92% of FY26 retail F&O losses came from options, the instrument scalping targets. A platform that makes rapid options execution effortless should not also make it reckless — this has to be designed against, not just disclaimed.
  • Risk
    Scalping volume collides directly with the new SEBI Algo framework's order-rate rules.Active scalpers can realistically exceed the 10 orders/second OPS threshold that triggers extra exchange tagging — this must be engineered for from day one, not patched in later.

    • Verdict: the pivot is directionally sound — there is proven willingness to pay for exactly this kind of tool — but entering as "yet another fast ladder" competes head-on with OptionX on its own turf. The differentiated entry point is combining that execution speed with the risk-management and compliance infrastructure GoTrading already has underway, which none of the scalper-focused incumbents lead with.

    07 — Strategy

    Recommended positioning

    Position GoTrading as the scalping terminal built for traders who got burned twice — once by slow, laggy broker apps, and once by a strategy that blew past its own risk limits because nothing was watching. Speed and safety, in one terminal, is the wedge neither camp currently owns:

    Execution speedRisk & compliance controls
    OptionX / Sahi / DhanStrongMinimal — basic SL only
    Sensibull / AlgoTestNot built for scalpingModerate (analytics-driven)
    GoTrading (target)Competitive (see §5)Strong — kill switch, daily loss limits, circuit breaker, Algo-ID compliance

    Target user: not the mass-market casual F&O punter (a shrinking, loss-making population SEBI is actively discouraging), but the semi-professional scalper and small systematic desk who trades daily volume, already knows what a price ladder is, and has been asking for a kill switch that actually works. Smaller, stickier, higher willingness-to-pay segment than the broad retail pool.

    Secondary track worth keeping open

    The original research also surfaced a B2B angle: sell the same multi-broker execution + risk + Algo-ID compliance layer as infrastructure to smaller brokers and RIAs who are now legally on the hook under SEBI's framework but under-resourced to build it. It doesn't compete with the scalper terminal for engineering effort — it's the same backend, a different front door — and is worth revisiting once the B2C product has proven reliability.

    09 — Engineering requirements

    Technical execution requirements

    To make the UX in §8 feel instant within the physics constraint from §5, the data and order path need real changes, not just UI polish — several of these close the P0/P1 gaps already catalogued in §1:

    • P0
      Decimal-safe money and a real order state machineReplace float-based amounts and the direct-to-"PLACED" order flow with Decimal types and a PENDING→SUBMITTED→ACCEPTED→FILLED lifecycle — non-negotiable before higher order volume touches real capital.
    • P0
      True WebSocket tick streaming with MessagePack payloadsThe dependency already exists (@msgpack/msgpack) but isn't wired into a real streaming path yet — replace React Query polling with persistent WS + binary frames for LTP, depth, and P&L.
    • P0
      Isolate the WS ingestion loop from strategy/business logicUse a ring buffer between the tick feed and any downstream processing so a slow consumer never blocks the socket callback thread — the repo's own audit flags this exact backpressure risk in fyers_stream.py.
    • P0
      Pre-validated, one-shot order submissionRisk checks (margin, position limits) run client-side optimistically against a cached snapshot, then confirmed server-side — avoids a synchronous DB round trip sitting in the critical path of every scalp order.
    • P1
      Startup reconciliation against live broker statePull actual positions/orders from each connected broker on restart instead of trusting the local DB, closing the reconciliation gap flagged in §1.
    • P1
      Per-symbol locking across concurrent strategiesPrevents two strategies (or a strategy and a manual scalp) from racing on the same instrument's order flow.
    • P1
      Move Greeks/indicator math off the Python GILThe repo's own Rust-migration proposal (docs/review/03-rust-migration.md) is directly relevant here — real-time Greeks recompute on every tick is exactly the workload that benefits from a PyO3 extension instead of asyncio.to_thread.
    • P1
      WebSocket reconnection with gap-fillOn reconnect, backfill missed ticks from the broker's REST snapshot before resuming the stream — silent gaps during a scalp are a direct P&L risk.
    • P2
      Latency telemetry per broker, per orderLog click-to-ack time per broker adapter; feeds both the §8 transparency feature and internal SLA monitoring.
    10 — Non-negotiable

    Compliance requirements

    SEBI's retail algo trading framework became fully mandatory on April 1, 2026. A scalping terminal generates order volume fast enough to hit its thresholds quickly, which makes this section P0 ahead of any UX work, not after it.

    • P0
      Exchange-issued Algo ID on every orderLegal requirement, not optional — every order the platform sends must carry a registered strategy's Algo ID.
    • P0
      Orders-per-second monitoring against the 10/sec thresholdA scalper hammering a ladder can cross this fast; the platform must throttle and flag before the exchange does, with the extra tagging the framework requires above threshold.
    • P0
      Hardened, auditable kill switchPer-strategy and global, both broker-registered and user-facing — currently a settings field, not a hardened control path.
    • P0
      Static IP allowlisting per broker connectionRequired by the framework for API-based algo access.
    • P1
      White-box strategy logic by defaultTransparent, disclosed strategy logic clears exchange registration far more easily than proprietary black-box logic, which requires SEBI Research Analyst registration.
    Precedent to avoid

    Tradetron received show-cause notices sent to 120+ brokers in October 2024 over strategies alleged to imply assured returns through its marketplace. If GoTrading ever adds a strategy marketplace or copy-trading feature, it must ship with disclosed track records, no performance guarantees in copy, and provider registration checks built into onboarding — not bolted on after scrutiny.
